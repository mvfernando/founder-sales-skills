# Product parameters

Copy and fill this block for each operational skill. `{{PARAMETERS}}` in a skill refers to **the filled block**. Assign owner, source and update date to each value; any blank field blocks actions that depend on it, never licenses a guess. Do not commit a filled copy with private data to a public repository.

```text
## Product parameters
PRODUCT: {{PRODUCT}} — factual name and description; source/date
ICP: {{ICP}} — segment and target decision-maker; source/date
PROBLEM: {{PROBLEM}} — observed pain or explicitly marked hypothesis
VALUE PROPOSITION: {{VALUE_PROPOSITION}} — allowed wording and limits
MATURITY: {{MATURITY}} — available / in validation / planned; evidence
SENDER: {{SENDER}} — approved account and visible identity
NOTIFY CHANNEL: {{NOTIFY_CHANNEL}} — channel, authorized recipient and post-send rule
APPROVER: {{APPROVER}} — role responsible for explicit authorization
CRM: {{CRM}} — system, owner, write rules and canonical source
CONTEXT FOLDER: {{CONTEXT_FOLDER}} — context, decisions, metrics and permissions
FORBIDDEN WORDS: {{FORBIDDEN_WORDS}} — terms and promises excluded from external text
APPROVED CLAIMS WITH SOURCE: {{APPROVED_CLAIMS}} — claim | source document | date | limit
PRICE POLICY: {{PRICE_POLICY}} — validated / in validation; communication and approval conditions
```

Also set pilot duration and criteria; success population, event and time window; contact cadence; channel limits; time zone; retention policy; and delivery channels. Any illustrative value is a method example, **not** your organization's approved threshold. Ask the owner to decide actual values.
