# Commercial Messages

Use the filled [product parameters](../../PARAMETERS.md) at runtime; `{{PARAMETERS}}` means that filled block, not the blank template.

> **Shared rule:** Read the filled `{{PARAMETERS}}` block, current context and decision log. Separate fact, hypothesis, proposal and decision; give the source, date and scope for every number. Editorial approval never authorizes sending. If sources conflict, stop the claim/action and request a decision. Without a connected tool, access or evidence, report a draft/pending item—never pretend an action happened. Every external send requires specific human approval of the exact content, recipient, channel and sender.

## Objective

Write human, brief, verifiable messages tailored to the recipient.

## When to use

First contact, reply, objection, reactivation or follow-up.

## Inputs

{{PARAMETERS}}, history, channel, goal, recipient status, sources and configured length limits.

## Output

Main and alternative versions, rationale, seven-point test, sources and pending items.

## Human approval

Editorial review and separate authorization for the exact version and recipient before sending.

## Common mistakes

Multiple questions; generic language; fabricated personalization; repeated pressure; treating editorial approval as send approval.

## Steps

1. Choose **one** desired outcome and check history, consent, pauses and earlier promises.
2. Build **sourced context → relevance to {{PROBLEM}} → one question → a light next step**; omit observations that lack a source.
3. For unanswered follow-up use editorial progression: (i) recall context, (ii) add a new question or resource, (iii) offer an easy exit and ask for the right person. Never exceed the approved cadence.
4. Cut clichés such as “revolutionary”, “leading” and “effortless”, plus {{FORBIDDEN_WORDS}}; make claims only from {{APPROVED_CLAIMS}}.
5. Apply seven tests: clarity, relevance, naturalness, specificity, single next step, proof and brevity. Rewrite and retest for two or more failures; fix any policy violation even if it is the only failure.
6. Submit for external text review, provide two versions and wait for explicit send authorization.
