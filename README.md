**Author:** Elio Fernandes (founder of Flix Home)

## What's inside

16 generic Markdown skill templates, a [product-parameters block](PARAMETERS.md), and a [workflow diagram](docs/workflow.md). These are **methods**, not configured integrations or permission to send. Fill parameters privately for your product; keep changing facts in a dated context pack and explicit decisions in a decision log. Each template has objective, trigger, inputs, output, human-approval gate, common mistakes, steps and a copy-paste prompt.

## Quick start

1. Pick **one** task you repeat.
2. Fill [PARAMETERS.md](PARAMETERS.md) privately with owner, source and date for each value (do not commit a filled copy with private data).
3. Copy the corresponding `SKILL.md` into your AI tool, alongside the filled parameters and current context.
4. Run one real case under supervision: compare claims and actions to sources and correct the method.
5. Only then schedule it, with the approval gate and least-privilege access intact.

## Install anywhere

- **ChatGPT:** create a Project or custom GPT; paste the skill into instructions or attach its Markdown file to the Project. Add filled parameters privately. Verify current menu names in the product.
- **Claude:** add it to a Project, or use its `SKILL.md` as a skill. In Claude Code place it at `.claude/skills/<name>/SKILL.md`; add filled parameters separately and check the current installation instructions.
- **Gemini:** create a Gem, paste the instructions and provide current parameters/context.
- **Spinnable:** send the `.md` file and say “save this as a skill”. Connect only needed tools, test under supervision, then choose a schedule if useful.
- **Any agent framework:** load the Markdown as task instructions, supply parameters/context at runtime and enforce the approval gate in the actual execution layer. A prompt alone is not an access-control mechanism.

## Operating principles

- **Honest maturity:** distinguish available, in validation and planned; proposals do not prove usage or revenue.
- **Human approval before any send:** editorial approval is not authorization; approve exact content, recipient, channel and sender each time.
- **Source for every number:** record period, counting rule, numerator/denominator and source; otherwise say “evidence missing”.
- **Hypothesis ≠ fact:** keep proposals, decisions and measured outcomes separate.
- **Least privilege:** limit access to necessary accounts/data, respect consent and verify destinations.
- **Honest failure:** without a tool, permission or source, return a pending item instead of claiming completion.
